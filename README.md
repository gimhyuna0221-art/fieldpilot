# FieldPilot

### 바이브코더를 위한 시장조사·의사결정 스킬

**“이거 이미 있나?”, “사람들이 왜 바꿔 쓰지?”, “더 만들어야 하나?”를 AI에게 물었을 때,  
그럴듯한 답보다 실제 경쟁·대체재·근거·반대근거를 먼저 찾도록 만든 스킬입니다.**

[결과 예시](examples/briefloop/README.md) · [설치](docs/INSTALL.md) · [기능 가이드](docs/FEATURE_GUIDE.md) · [검증/변경 기록](docs/RELEASE_NOTES.md)

> 현재 프로필: `1.9.9-rc04` + `competitor-coverage-01-r2` + `quality-max-01`

---

## 왜 FieldPilot인가

일반 AI도 시장조사를 할 수 있습니다. FieldPilot은 **시장조사를 더 길게 쓰는 것**보다 아래 차이를 만들려고 합니다.

### 1. 카테고리 이름만 같은 경쟁사를 찾지 않습니다

제품을 실제로 겹치는 요소로 나눠 봅니다.

- 같은 고객이 같은 문제를 해결하는 **직접 경쟁사**
- 다른 방식으로 같은 일을 해결하는 **대체재**
- 특정 워크플로·메커니즘·장르·사용경험이 닮은 **인접 레퍼런스**
- 전체 제품은 달라도 한 요소를 잘 구현한 **component / cross-category reference**

예를 들어 게임이라면 장르만 맞추는 대신 전투, 성장루프, 소셜 구조, 카메라/조작, 분위기, 과금처럼 실제 경험을 만드는 요소를 나눠 대표 사례를 찾습니다.

### 2. 이미 더 잘 조사된 자료가 있으면 먼저 씁니다

FieldPilot이 모든 것을 새로 생성할 필요는 없습니다.

공식 통계, 전문 리서치, 경쟁사 원문, 리뷰·커뮤니티, 기존 시장정보 서비스처럼 **그 질문을 더 잘 답하는 자료나 도구가 있으면 먼저 찾아 검증**합니다. 부족한 부분만 추가 조사합니다.

### 3. “있다”와 “팔린다”를 구분합니다

다음은 같은 증거가 아닙니다.

```text
경쟁사 가격표
≠ 실제 결제
≠ 반복 구매/리텐션
≠ 검증된 지불의사
```

출처를 찾지 못했거나 정의·기간·지역이 맞지 않으면 그대로 미확인으로 남깁니다. 유리한 자료만 모으지 않고 반대 근거도 같이 봅니다.

### 4. 조사에서 끝나지 않고 다음 결정을 연결합니다

결과는 보통 다음 질문으로 이어집니다.

- 지금 더 만들어야 하는가?
- 어떤 기능은 미뤄야 하는가?
- 고객이 기존 대안에서 바꿀 이유가 있는가?
- 가격을 판단하기 전에 무엇이 비어 있는가?
- 광고 문제인가, 제품 문제인가, 측정 문제인가?
- 어떤 증거가 나오면 현재 결론을 뒤집어야 하는가?

전체 시장조사가 필요하면 Markdown/HTML/PDF 등 실행 환경에서 실제로 만들 수 있는 형식의 보고서로 정리할 수 있습니다.

## 외부 파일럿에서 반복해서 나온 신호

현재까지 외부 테스터 2명의 정성 피드백에서 공통적으로 강점으로 나온 부분은 **유사·인접 제품 발견력**이었습니다.

> “완전히 모르고 있었던 겹치는 장르를 잘 찾아냄. 겹치는 요소마다 대표적인 게임들을 가져와서 비교해줌.”

> “진짜 샅샅이 뒤져서 비슷한 느낌의 제품을 다 찾아줌.”

반대로 사용량을 줄이는 데 집중한 버전은 **결과가 덜 풍부하고 일반 ChatGPT와 차이가 작게 느껴진다**는 피드백이 있었습니다.

그래서 `quality-max-01`부터는 **사용량 최소화보다 발견력·비교 깊이·판단에 필요한 세부 근거를 우선**합니다. 중복 검색과 반복 읽기는 줄이지만, 유용한 경쟁사·대체재·레퍼런스를 토큰 절약 때문에 잘라내지 않습니다.

> 이 피드백은 정성적 파일럿 신호입니다. 일반 AI 대비 우월성, 시장 전체 선호, 결제 의사 또는 정확한 성능 향상을 입증한 자료는 아닙니다.

## 빠르게 시작하기

FieldPilot은 Claude Code 또는 로컬 Skills를 지원하는 Codex에서 사용할 수 있습니다.

### 1. 저장소 받기

```bash
git clone https://github.com/gimhyuna0221-art/fieldpilot.git
cd fieldpilot
```

### 2. `skills/fieldpilot` 폴더 전체 설치

| 환경 | 프로젝트 안 설치 위치 | 호출 |
|---|---|---|
| Claude Code | `.claude/skills/fieldpilot/` | `/fieldpilot` |
| Codex | `.agents/skills/fieldpilot/` | `$fieldpilot` 또는 스킬 선택 |

`SKILL.md` 하나만 복사하지 마세요. 조사 규칙, 참고 자료, 계산·보고서 도구가 함께 있어야 합니다.

자세한 설치 방법은 [INSTALL.md](docs/INSTALL.md)를 참고하세요.

### 3. 평소 말로 질문하기

```text
/fieldpilot

프리랜서가 고객 수정 요청을 한곳에 모아보는 웹앱 만들었어.
한국에서 월 9,900원에 팔고 싶은데 이미 비슷한 게 많나?
무료 대안까지 비교하고, 더 만들기 전에 뭘 확인해야 할지 봐줘.
```

시장조사 용어나 긴 프롬프트를 외울 필요는 없습니다.

## 어떤 결과를 받게 되나

질문에 따라 필요한 것만 고르지만, 넓은 제품·시장 판단에서는 보통 아래를 다룹니다.

| 보고 싶은 것 | FieldPilot이 확인하는 것 |
|---|---|
| 경쟁 | 직접 경쟁사, 대체재, 수작업/무료 방법, 인접 레퍼런스 |
| 겹치는 요소 | 어떤 장르·메커니즘·워크플로·가격·사용경험이 겹치는지 |
| 고객 | 누가 어떤 상황에서 이 문제를 겪는지, 사용자와 결제자가 다른지 |
| 가격/돈 | 실제 가격 조건, 무료 대안, 전환비용, 확인된 결제 증거 수준 |
| 제품 차이 | 이미 있는 것, 부족한 것, 아직 확인되지 않은 차이 |
| 반대 근거 | 왜 안 바꿔 쓸 수 있는지, 왜 시장이 작거나 접근이 어려울 수 있는지 |
| 판단 | 계속 만들 것 / 바꿀 것 / 보류할 것 |
| 다음 행동 | 현재 결론을 가장 빨리 검증하거나 뒤집을 한 가지 행동 |

출처와 미확인 사항을 남겨 **나중에 다시 확인할 수 있는 판단**을 만드는 것이 목표입니다.

## 작동 방식

```text
사용자의 제품·고민
        ↓
현재 상태와 결정 복원
        ↓
이미 있는 좋은 자료·전문 서비스 우선 탐색
        ↓
직접 경쟁사 + 대체재 + 인접/교차 카테고리 레퍼런스 탐색
        ↓
고객·가격·시장·제품 상태·반대 근거 검증
        ↓
확인된 사실 / 해석 / 미확인 분리
        ↓
BUILD / CHANGE / HOLD 범위
        ↓
다음 검증 행동
        ↓
필요하면 전문 보고서
```

모든 기능을 매번 돌리지는 않습니다. 현재 질문과 판단에 필요한 경로만 선택합니다.

## Quality Max: 짧게보다 잘 찾는 것을 우선합니다

기본 우선순위는 다음과 같습니다.

```text
정확성·출처
→ 결정에 필요한 범위
→ 경쟁/대체/레퍼런스 발견력
→ 세부 비교
→ 의사결정 가치
→ 효율
```

효율화 대상은 **중복**입니다.

- 같은 검색을 표현만 바꿔 반복
- 같은 제품을 여러 이름으로 중복 집계
- 이미 읽은 변경 없는 자료 재독
- 결론에 아무 영향이 없는 장황한 설명

반대로 아래는 단순히 토큰을 줄이기 위해 삭제하지 않습니다.

- 새로 발견된 중요한 경쟁사·대체재
- 예상하지 못한 겹치는 장르/카테고리
- 요소별 대표 레퍼런스
- 결론을 뒤집을 수 있는 반대 근거
- 실제 판단에 필요한 세부 비교

좁은 사실 질문까지 무조건 길게 만들지는 않습니다. **넓은 조사에서만 필요한 만큼 깊게 갑니다.**

## 필요한 경우 추가로 쓰는 분석

FieldPilot은 하나의 거대한 고정 보고서를 매번 실행하지 않습니다.

| 필요할 때 | 추가 분석 |
|---|---|
| 여러 판단 원칙으로 결론 재검토 | Evidence-Grounded Decision Council |
| 가격/기능 선택 뒤 반응 가정 검토 | Scenario Stress Test |
| 실제 가입·행동 기록 분석 | Funnel / retention event analysis |
| 후기·인터뷰 원문 분석 | Qualitative evidence synthesis |
| 설문/조사 설계 | Primary research design |
| 설문 결과 분석 | Crosstab / weighting / open-text analysis |
| 경쟁사 변경 비교 | Research refresh / change impact |
| 전문 시장조사 납품 | Professional report pipeline |

세부 사용법은 [FEATURE_GUIDE.md](docs/FEATURE_GUIDE.md)에 정리되어 있습니다.

## 결과 예시

[BriefLoop 시장조사 예시](examples/briefloop/README.md)는 프리랜서가 고객 수정 요청을 관리하는 가상의 웹앱을 대상으로 만든 내부 예시입니다.

예시는 다음을 보여주기 위한 것입니다.

- 무료 폼·협업 도구까지 대안으로 보는 방식
- 가격이 싸다는 사실과 실제 결제 수요를 구분하는 방식
- 첫 고객군과 전환 이유를 좁히는 방식
- 출처표와 보고서를 함께 남기는 방식

이 예시는 실제 고객 성과나 최신 Quality Max가 일반 AI보다 우수하다는 증거가 아닙니다.

## 요구 사항

- Claude Code 또는 로컬 Skill을 지원하는 Codex
- 최신 공개자료 조사를 위한 웹 검색/원문 접근 기능
- 보조 도구 사용 시 Python 3.10+
- PDF 생성 시 호환되는 로컬 브라우저 환경

FieldPilot 자체에 유료 데이터베이스, 패널 응답, 경쟁사의 비공개 자료, 별도 AI 이용권은 포함되지 않습니다.

---

## 현재 한계

- 결과 품질은 사용하는 AI 모델, 웹/파일 도구, 접근 가능한 자료에 영향을 받습니다.
- 로그인·유료 자료·비공개 데이터는 별도 권한이 필요합니다.
- 실제 고객 인터뷰·결제·사용기록이 없으면 수요·매출·PMF를 확정할 수 없습니다.
- 조사 범위가 넓으면 시간과 AI 사용량이 증가할 수 있습니다.
- 현재 외부 파일럿은 유사/인접 제품 발견력에 대한 긍정 신호를 줬지만, 최신 버전의 일반 AI 대비 우월성이나 지불의사는 독립적으로 확립되지 않았습니다.
- FieldPilot은 SurveyMonkey/Qualtrics 같은 설문 인프라, Similarweb 같은 독점 데이터, 전문 리서치 회사의 비공개 데이터베이스를 대체하지 않습니다. 필요한 경우 그런 전문 자료와 도구를 조사 과정에 활용하는 쪽을 지향합니다.
