# FieldPilot

### 바이브코더를 위한 시장조사 스킬

“앱 만들었는데 아무도 안 써.” “이거 돈 될까?” “광고부터 해야 돼?”

만드는 건 AI와 같이 했는데, 팔릴지 판단하는 건 여전히 막막할 때 씁니다. FieldPilot은 Claude Code나 Codex 안에서 경쟁 서비스와 공개 자료를 조사하고, 가격과 홍보 방법, 다음에 확인할 일을 정리해 주는 스킬입니다.

시장 규모, 고객, 경쟁사, 시장 트렌드, 수익성, 진입장벽 같은 기본 분석부터 **여러 시장조사 도구와 경쟁 서비스의 강점까지 흡수해 하나의 조사 흐름으로 묶었습니다.** 넓은 시장 질문에서는 제품·대체재 판단만으로 끝내지 않고, 필요할 때 시장 구조·규모/성장·기업용 대안·보안/규제·기술 변화까지 한 단계 더 확인하는 산업 심층 백스톱을 적용합니다.

[결과 예시 보기](examples/briefloop/README.md) | [설치하기](#설치하기) | [이럴 때 써보세요](#이럴-때-써보세요) | [현재 한계](#현재-한계)

본인 사업과 내부 업무에 무료로 사용할 수 있습니다. 스킬 파일 자체의 재판매는 허용하지 않습니다. 자세한 범위는 [이용 조건](LICENSE.md)을 확인하세요.

## 개떡같이 말해도 괜찮아요

시장조사 용어나 긴 프롬프트를 외울 필요는 없습니다. 제품과 고민을 평소 말로 알려주세요. 파일럿이 상황을 파악하고, 직접 찾을 수 있는 정보는 먼저 조사합니다. 판단에 꼭 필요한 내용이 빠져 있다면 그 부분만 물어보도록 만들었습니다.

```text
/fieldpilot
프리랜서가 고객 수정 요청을 모아 보는 웹앱 만들었어.
한국에서 월 9,900원에 팔고 싶은데, 이미 비슷한 게 많나?
뭘 더 만들기 전에 확인해야 할지 봐줘.
```

결과에는 이런 내용이 담깁니다.

- 고객이 지금 쓰는 경쟁 제품과 무료 대안
- 내 제품으로 바꿀 이유와 바꾸지 않을 이유
- 가격이나 기능을 정할 때 참고할 근거와 출처
- 아직 확인하지 못한 것, 먼저 시험할 것과 보류할 것

전체 보고서가 필요하면 “시장조사 보고서 파일로 줘”라고 덧붙이면 됩니다. 조사 범위와 실행 환경에 따라 보고서와 표 파일로 정리합니다.

# FieldPilot 사용 설명서

## 1. 먼저 최신 스킬이 불러와지는지 확인하세요

이번 설명의 기준은 다음 버전입니다.

- 기본 버전: `1.9.9-rc04`
- 경쟁사 방법 반영 버전: `competitor-coverage-01-r2`
- 품질 우선 프로필: `quality-max-01`
- 산업 심층 백스톱: `industry-depth-backstop-01`

[최신 공개 저장소](https://github.com/gimhyuna0221-art/fieldpilot)에서 받은 `skills/fieldpilot` 폴더 전체가 설치되어 있어야 합니다. `SKILL.md` 하나만 복사하면 필요한 참고 자료와 계산 도구가 빠집니다.

| 사용하는 환경 | 프로젝트 안의 설치 위치 | 호출 방법 |
|---|---|---|
| Claude Code | `.claude/skills/fieldpilot/` | `/fieldpilot` |
| Codex | `.agents/skills/fieldpilot/` | `$fieldpilot` 또는 스킬 선택 메뉴 |

기존 버전이 있다면 별도로 백업한 뒤 교체하고, 새 대화에서 확인하는 편이 좋습니다. 일반 ChatGPT나 Claude 웹 대화에 ZIP을 첨부하는 것과, 코드 실행 환경에 스킬을 설치하는 것은 다릅니다.

처음에는 이렇게 요청하세요.

> FieldPilot을 사용해줘. 시작하기 전에 실제로 불러온 SKILL.md의 경로와 버전을 확인해줘. competitor_extension_revision이 competitor-coverage-01-r2, quality_extension_revision이 quality-max-01, industry_depth_extension_revision이 industry-depth-backstop-01인지도 확인하고, 이전 버전이 불러와졌다면 먼저 알려줘.

AI가 “최신입니다”라고만 답하는 것보다 **실제로 읽은 파일 경로와 버전**을 보여주는지 확인하세요.

## 2. 기본 사용법은 어렵지 않습니다

아래 세 가지만 알고 있는 만큼 전달하면 됩니다.

1. 무엇을 만들었거나 만들려고 하는지
2. 지금 무엇이 고민인지
3. 이미 가지고 있는 자료가 무엇인지

예를 들어 이렇게 시작하면 됩니다.

> 한국 프리랜서가 고객의 수정 요청을 받는 웹서비스를 만들었어. 월 9,900원을 받을까 고민 중이야. 아직 실제 사용자는 없어. 첨부한 설명을 보고 무료 대안과 비교해서, 지금 돈을 받아도 될지와 먼저 고칠 부분을 조사해줘.

서비스 주소, 기존 보고서, 고객 피드백이 있으면 그대로 붙이면 됩니다. 사용자가 다시 요약할 필요는 없습니다.

**아래의 긴 요청문은 기능을 이해하고 원하는 결과를 분명하게 요청하기 위한 예시입니다. 이런 전문적인 문장을 써야만 분석을 받을 수 있다는 뜻은 아닙니다.**

어떤 기능을 사용할지는 다음처럼 구분하면 쉽습니다.

| 알고 싶은 것 | 사용하면 되는 분석 | 필요한 재료 |
|---|---|---|
| 가격이나 기능을 바꾸면 어떤 문제가 생길까? | 가상 시나리오 검토 | 비교할 선택지, 제품 설명, 조사 근거 |
| 이 결론에서 놓친 것은 없을까? | 여러 판단 관점으로 재검토 | 현재 결론과 근거 |
| 가입한 사람이 어디에서 나갈까? | 이용 기록 분석 | 실제 행동 기록 |
| 고객들이 공통으로 불편해하는 것은 뭘까? | 후기와 인터뷰 분석 | 실제 발언 원문 |
| 사람들이 어떤 고민으로 검색할까? | 검색 의도 분석 | 검색어 자료 또는 접근 가능한 공개 자료 |
| 경쟁사가 바뀌었는데 나도 바꿔야 할까? | 경쟁사 변경 비교 | 이전 자료와 최신 자료 |
| 가격과 기능을 고객에게 어떻게 물어볼까? | 조사 설계 | 확인할 질문, 제품과 가격 후보 |
| 조사 내용을 한 번에 보고 싶다 | 전체 시장조사 보고서 | 제품 설명과 기존 자료 |

## 3. MiroFish에서 참고한 기능: 선택 이후의 반응 살펴보기

### 언제 쓰나요?

결정을 내리기 전에 그 선택이 다른 사람의 행동에 어떤 영향을 줄지 살펴보고 싶을 때 사용합니다.

예를 들면 다음과 같습니다.

- 가격을 내릴지 유지할지 고민할 때
- 무료 기능을 어디까지 제공할지 정할 때
- 특정 고객군에 집중할지 넓게 판매할지 정할 때
- 경쟁사가 비슷한 기능을 출시했을 때

### 무엇을 주면 되나요?

비교할 선택지와 현재 상황을 줍니다. 이전 시장조사 보고서가 있다면 함께 전달하세요.

BriefLoop라면 다음처럼 요청할 수 있습니다.

> 첨부한 BriefLoop 보고서를 바탕으로, 월 9,900원을 받는 안과 무료로 한 프로젝트를 제공하는 안을 비교해줘.  
> 먼저 기존 조사에서 쓸 수 있는 근거를 확인하고, 판단에 필요한 최신 정보만 추가로 찾아줘.  
> 각 안에서 프리랜서와 그 고객이 어떻게 반응할 수 있는지, 그 반응 때문에 다음에 어떤 문제가 생길 수 있는지 살펴봐줘.  
> 가정과 확인된 사실을 구분하고, 실제로 무엇을 확인해야 두 안 중 하나를 고를 수 있는지도 정리해줘.

여기서 무료 한 프로젝트는 **검토할 선택지의 예시**이지, BriefLoop에 이미 있는 기능이라는 뜻이 아닙니다.

### 어떤 결과를 받아야 하나요?

- 각 선택지에서 기대하는 효과
- 그 효과가 생기려면 필요한 조건
- 고객이 받아들이지 않을 수 있는 이유
- 다른 대안이나 경쟁사의 대응이 미칠 영향
- 현재 판단을 뒤집을 수 있는 증거
- 실제로 확인할 다음 항목

예를 들어 “무료로 시작하면 진입 부담은 줄 수 있지만, 유료로 바꿀 이유가 약해질 수 있다”는 식으로 선택의 양면을 검토하는 것입니다.

### 무엇을 하면 안 되나요?

“가상 고객 100명 중 70명이 구매했으니 성공 가능성 70%”처럼 받아들이면 안 됩니다.

이 기능은 **조사 근거를 바탕으로 가능한 반응을 검토하는 사고 실험**입니다. 실제 고객 조사나 미래 예측이 아닙니다. MiroFish의 시뮬레이션 프로그램이 뒤에서 자동으로 실행되는 것도 아닙니다.

근거가 너무 부족하면 시나리오를 억지로 만들기보다, 어떤 사실부터 확인해야 하는지 알려주는 것이 맞습니다.

## 4. theboardroom에서 참고한 기능: 같은 결론을 다른 관점으로 검토하기

### 언제 쓰나요?

“조사 결과는 나왔는데, 한쪽 생각에 치우친 것은 아닐까?” 싶을 때 사용합니다.

가상 시나리오와는 다릅니다.

- 가상 시나리오: 내가 선택한 뒤 어떤 반응이 이어질까?
- 여러 판단 관점: 지금 이 선택에서 무엇을 중요하게 보고, 무엇을 놓치고 있을까?

### 어떻게 요청하나요?

> 이 보고서의 현재 결론을 먼저 요약해줘. 그다음 공개된 원문으로 확인할 수 있는 판단 원칙 중 이 결정에 맞는 관점 2~3개를 골라 재검토해줘.  
> 각 관점이 중요하게 보는 것, 기존 결론에 반대하는 이유, 서로 의견이 갈리는 부분을 보여줘.  
> 마지막에는 유명한 사람의 의견이나 다수결이 아니라 실제 근거를 기준으로 결론을 정리해줘.

### 어떤 결과를 받아야 하나요?

- 원래의 판단
- 선택한 관점과 그 원출처
- 각 관점이 드러낸 위험이나 놓친 조건
- 의견이 일치하는 부분과 갈리는 부분
- 최종 판단이 바뀌었는지, 바뀌었다면 이유

예를 들어 고객이 얻는 이익을 중심으로 보면 편의성이 중요할 수 있고, 초기 사업의 운영 부담을 중심으로 보면 지원에 드는 시간이 더 중요할 수 있습니다.

### 주의할 점

실제 전문가가 참여하거나 자문한 결과가 아닙니다. 여러 관점이 동의했다고 사실이 더 확실해지는 것도 아닙니다.

또 **여러 관점으로 검토하는 것과 여러 AI 모델이 독립적으로 검증하는 것은 다릅니다.** 이 기능만으로 독립 검토가 자동 수행됐다고 볼 수는 없습니다.

## 5. Mixpanel과 Amplitude에서 참고한 기능: 어디서 빠지고 다시 오는지 계산하기

이 기능은 실제 이용 기록이 있어야 합니다. 서비스 설명이나 시장조사 보고서만으로는 계산할 수 없습니다.

### ① 먼저 행동 기록을 준비합니다

예를 들어 다음 행동을 기록한 자료입니다.

- 가입
- 첫 프로젝트 생성
- 첫 요청 접수
- 결제
- 다시 방문하거나 핵심 기능 사용

이미 분석 서비스나 데이터베이스에 기록이 있다면, 접근 권한이 있는 자료를 내보내 전달하면 됩니다. 내보내기 방법은 사용하는 서비스와 계정에 따라 달라집니다.

내장 계산기가 사용하는 형식은 다음과 같습니다. 아래 행은 설명용 가상 데이터입니다.

```csv
event_id,unit_id,event,timestamp
e001,U001,signup,2026-09-01T09:00:00+09:00
e002,U001,project_created,2026-09-01T09:10:00+09:00
e003,U001,request_received,2026-09-01T10:00:00+09:00
e004,U001,return,2026-09-02T10:00:00+09:00
```

| 열 이름 | 뜻 |
|---|---|
| `event_id` | 행동 기록마다 붙은 고유 번호 |
| `unit_id` | 같은 사용자를 구분하는 번호. 분석 목적에 따라 계정 번호를 사용할 수도 있음 |
| `event` | 어떤 행동이 일어났는지 |
| `timestamp` | 그 행동이 일어난 시각과 시간대 |

이름과 이메일을 사용할 필요는 없습니다. 같은 사람의 기록을 연결할 수 있는 가명 번호로 충분합니다.

원본 파일의 형식이 다르다고 직접 고칠 필요는 없습니다. FieldPilot에 원본을 읽고 열을 맞춰 달라고 요청하세요. 다만 원본에 없는 사용자 번호나 시각을 AI가 지어내면 안 됩니다.

### ② 무엇을 계산할지 말합니다

> 첨부한 이용 기록으로 가입 → 프로젝트 생성 → 첫 요청 접수 순서에서 어디에 가장 많이 멈추는지 분석해줘. 가입 후 72시간 안에 진행한 행동을 기준으로 봐줘.  
> 먼저 기록의 열과 이벤트 의미를 확인하고, 원본은 보존한 채 계산용 파일을 따로 만들어줘. 테스트 계정과 중복 기록은 어떻게 처리했는지 남겨줘.  
> 아직 72시간이 지나지 않은 신규 가입자는 실패한 사용자와 구분해줘.  
> 첫 가입 후 24시간부터 48시간 사이에 return 기록이 있는 비율도 따로 계산해줘. 계산 결과와 원래 기록을 대조할 수 있는 표를 함께 줘.

실제 기록에서 행동 이름이 다르면 그 이름에 맞춰 분석해야 합니다.

### ③ 결과에서 확인할 것

- 분석 대상이 몇 명인지
- 각 단계까지 간 사람이 몇 명인지
- 비율을 어떤 인원으로 나눴는지
- 아직 관찰 기간이 끝나지 않은 사람은 몇 명인지
- 제외한 기록과 이유
- 기록 누락 가능성이 있는지
- 다음에 확인하거나 고칠 부분

비율만 보면 안 됩니다. `50%`라도 2명 중 1명인지, 1,000명 중 500명인지 의미가 다릅니다.

### 내장 계산기의 정확한 범위

현재 포함된 도구는 다음을 계산합니다.

- 첫 진입을 기준으로 정해진 행동을 순서대로 거친 비율
- 정해진 시간 안에 마지막 단계까지 도달했는지
- 첫 진입 후 특정 24시간 구간에 다시 활동했는지
- 중복 기록, 관찰 기간 부족, 집계 대상에서 빠진 기록

다음은 자동 지원한다고 생각하면 안 됩니다.

- Mixpanel이나 Amplitude 계정 자동 연결
- 앱에 이용 기록 수집 기능 자동 설치
- 로그인 전후 사용자를 자동으로 같은 사람으로 연결
- 매출, 이익, 광고 기여도 계산
- 이탈 원인의 인과관계 입증
- 모든 종류의 재방문 지표

특히 현재 도구의 1일차 재방문은 **첫 진입 후 24시간 이상, 48시간 미만**입니다. “달력상 다음 날”과는 다릅니다. 원하는 기준이 다르면 AI가 이 차이를 설명하고 맞는 계산 방법을 사용해야 합니다.

기록이 없다면 이렇게 요청하세요.

> 아직 이용 기록이 없어. 우리 서비스에서 어떤 행동을 기록해야 가입, 첫 사용, 재방문을 구분할 수 있는지 정리해줘. 개발 AI에게 넘길 이벤트 이름과 발생 조건, 확인 방법까지 작성해줘. 지금 실제 데이터를 수집한 것처럼 분석하지는 마.

이 경우 받는 것은 **분석 결과가 아니라 측정 설계**입니다.

### 무엇을 준비하나요?

가지고 있는 자료부터 쓰면 됩니다.

- 테스터 피드백

- 인터뷰 기록

가능하면 발언 원문과 구분 번호, 발언이 나온 상황을 함께 주세요.

기록 번호: T01

### 어떤 결과를 받아야 하나요?

| 문제 | 근거가 된 발언 | 해당 자료 안의 인원 | 반대 사례 | 개선 후보 |
|---|---|---|---|---|

여기서 중요한 것은 원문까지 돌아갈 수 있어야 한다는 점입니다.

“고객은 가격에 민감하다”라는 요약만 있으면 부족합니다. 누가 어떤 상황에서 무엇이라고 말했는지 확인할 수 있어야 합니다.

- 불만이 많다고 반드시 구매를 막는 가장 큰 원인이라고 단정할 수는 없습니다.
- 녹음만 있다면 사용하는 AI 환경이 녹음을 읽거나 전사할 수 있는지 확인해야 합니다. 이 스킬 자체에 별도의 음성 전사 프로그램이 들어 있는 것은 아닙니다.
- 비공개 고객 자료는 처리 권한을 확인하고 개인정보와 기밀을 최소화해 전달하세요.

## 7. ListeningMind에서 참고한 기능: 검색어 뒤의 고민 이해하기

### 무엇을 준비하나요?

검색어 자료가 있다면 가장 좋습니다.

- 내 사이트로 들어온 검색어
- 검색어별 노출과 클릭 자료
- 접근 권한이 있는 키워드 도구의 내보내기 파일
- 출처와 날짜가 있는 검색 자료

자료마다 지역, 기간, 숫자의 뜻이 다를 수 있으므로 이 정보도 함께 있어야 합니다.

### 어떻게 요청하나요?

> 첨부한 검색어 자료에서 사람들이 어떤 문제를 해결하려는지 분류해줘. 문제를 알아보는 검색, 해결 도구를 비교하는 검색, 구매를 고민하는 검색, 사용 중 막혀서 하는 검색을 구분해줘.  
> 브랜드 이름이 들어간 검색과 그렇지 않은 검색도 나눠줘. 각 묶음의 원래 검색어를 남기고, 우리 서비스에서 설명하거나 개선해야 할 내용과 연결해줘.  
> 실제 이동 경로가 없는 자료라면 검색 순서를 만들어 사실처럼 쓰지 마.

### 무엇을 얻나요?

- 사람들이 사용하는 표현
- 같은 표현처럼 보여도 다른 고민
- 비교 대상이 되는 대안
- 소개 페이지에서 답해야 할 질문
- 콘텐츠로 다룰 만한 주제

자료가 없다면 이렇게 시작할 수 있습니다.

> 별도 키워드 자료는 없어. 접근 가능한 공개 검색 자료부터 확인해서 고객이 어떤 말로 문제를 찾는지 조사해줘. 실제 검색량이나 이동 경로를 확인하지 못한 부분은 구분해줘.

### 중요한 한계

“이 검색어와 저 검색어가 관련 있다”와 “같은 사람이 이 순서로 검색했다”는 다른 주장입니다.

FieldPilot에 ListeningMind의 비공개 데이터가 기본 제공되는 것은 아닙니다. **확보한 자료 범위 안에서 검색 의도를 분석하는 기능**입니다.

## 8. Crayon에서 참고한 기능: 경쟁사 변경이 내 선택에 미치는 영향 확인하기

- 지난번 저장한 가격표나 화면
- 이전 시장조사 보고서
- 경쟁사의 현재 공식 페이지
- 각각의 확인 날짜

### 어떻게 요청하나요?

> 첨부한 지난달 경쟁사 자료와 현재 공식 페이지를 비교해줘. 가격, 이용 한도, 포함 기능, 대상 고객이 달라진 부분을 찾아줘.

### 어떤 결과를 받아야 하나요?

| 비교 항목 | 이전에 확인한 내용 | 현재 확인한 내용 | 근거 | 내 제품에 미치는 영향 |
|---|---|---|---|---|

“경쟁사가 기능을 추가했다”에서 끝나지 않고, 그 기능 때문에 내 고객의 선택이 달라질 근거가 있는지까지 연결하는 것입니다.

대화를 닫아도 계속 감시하려면 별도의 예약 실행이 실제로 설정되어 있어야 합니다. 스킬을 설치한 것만으로 상시 감시가 시작되지는 않습니다.

## 9. 오픈서베이, Quantilope, JMP에서 참고한 기능: 제대로 물어보고 비교할 조사 만들기

이 부분은 **조사 설계**, **실제 응답 수집**, **응답 분석**을 나눠 이해하면 됩니다.

### ① 먼저 무엇을 알고 싶은지 말합니다

방법 이름을 몰라도 됩니다.

> BriefLoop의 월 9,900원 가격이 부담인지, 아니면 기능이 부족해서 결제하지 않을지가 궁금해.  
> 공개 자료로 알 수 있는 것부터 확인하고, 그것만으로 판단이 안 되는 부분은 어떤 조사로 확인할지 비교해줘. 가격과 기능을 한꺼번에 섞어서 엉뚱한 결론이 나오지 않도록 해줘.

FieldPilot은 확인할 질문에 맞춰 방법을 제안해야 합니다. 무조건 설문부터 만들거나 어려운 통계 이름을 나열하는 것이 목적은 아닙니다.

예를 들어 다음 질문은 서로 다릅니다.

| 알고 싶은 것 | 고려할 수 있는 조사 |
|---|---|
| 무엇 때문에 불편한가? | 인터뷰, 실제 사용 과정 관찰 |
| 어떤 기능을 더 중요하게 보는가? | 기능 비교 질문, 조건이 맞으면 MaxDiff 설계 |
| 가격과 기능을 묶어서 어떤 구성을 선택하는가? | 조건이 맞으면 컨조인트 또는 선택 실험 설계 |
| 소개 문구 A와 B 중 실제 행동을 더 만드는 것은? | 조건이 맞으면 무작위 비교 시험 |
| 실제로 돈을 내는가? | 명확한 조건에서의 실제 구매 관찰 |

이는 질문에 따른 방법 예시입니다. 모든 상황에 고급 분석이 필요한 것은 아닙니다.

### ② 방법을 선택하거나 선택을 맡깁니다

> 내 상황에서 실행 가능한 방법을 골라줘. 조사 대상 조건, 질문 문구, 질문 순서와 분기, 응답 기록 양식, 분석 방법까지 준비해줘. 실제 모집이나 설문 발송은 하지 말고 설계만 해줘.

이렇게 요청하면 다음 자료를 받을 수 있어야 합니다.

- 누구에게 물어볼지
- 어떤 사람은 조사 대상에서 제외할지
- 실제로 사용할 질문
- 응답에 따라 넘어갈 다음 질문
- 응답을 기록할 표
- 중복이나 부실 응답을 검토할 기준
- 어떤 결과가 나오면 판단을 바꿀지
- 이 조사로도 알 수 없는 것

### ③ 실제 응답을 받은 뒤 다시 가져옵니다

> 이건 실제로 받은 응답이야. 설문 문항과 질문 분기 설명도 같이 첨부했어. 원본을 보존하고 중복, 결측, 질문을 보지 않은 사람부터 확인해줘.  
> 각 결과가 몇 명을 기준으로 계산됐는지 보여주고, 설문에 답한 사람들의 의견과 실제 구매 행동을 구분해줘. 이전 보고서에서 바뀌어야 할 판단만 갱신해줘.

응답 파일만으로 질문의 의미를 알 수 없다면 설문 문항과 선택지 정보도 필요합니다.

### 고급 분석에서 특히 알아둘 점

현재 스킬에 방법론과 실행 조건이 정리돼 있다는 것이 **JMP 같은 통계 프로그램 전체가 내장됐다는 뜻은 아닙니다.**

예를 들어 MaxDiff를 계산하려면 실제로 어떤 항목 묶음을 보여줬고, 응답자가 무엇을 가장 좋고 나쁘다고 골랐는지 기록이 있어야 합니다. 단순 별점 설문을 MaxDiff 결과라고 바꿔 부를 수는 없습니다.

자료나 실행 도구가 부족하면 FieldPilot은 다음 중 하나를 해야 합니다.

- 가능한 범위의 기초 분석을 수행
- 올바른 조사 설계를 작성
- 필요한 전문 도구와 입력 자료를 정리
- 외부 분석가가 무엇을 계산하고 무엇을 돌려줘야 하는지 의뢰서 작성

**계획만 작성했는데 분석을 완료했다고 하면 안 됩니다.**

설문 발송, 참여자 모집, 유료 패널 구매, 외부 서비스로 자료 업로드는 별도의 실행과 권한이 필요합니다.

- 출처와 조사 범위
- 실제 열리는 보고서 파일

GPT Researcher나 STORM 프로그램이 자동으로 설치되거나 실행되는 것은 아닙니다. 여러 질문으로 나눠 조사하고, 근거를 연결해 보고서로 만드는 방식을 참고한 것입니다.

### 보고서와 제품 이미지는 별개입니다

- 보고서: 분석 내용 전체
- HTML 또는 PDF: 보고서를 읽기 좋게 만든 파일
- 제품 이미지: 보고서 일부를 보여주는 홍보용 미리보기

앞에서 만든 BriefLoop 제품 이미지는 세 번째에 해당합니다. 이미지에 내용을 보기 좋게 배치했다고 새로운 조사 결과가 생기는 것은 아닙니다.

[보고서 납품 지침](skills/fieldpilot/references/modules/MARKET_RESEARCH_DELIVERABLES.md)

## 11. 이미 받은 보고서에 필요한 기능만 추가할 수도 있습니다

지금 가진 BriefLoop 보고서를 처음부터 다시 조사할 필요는 없습니다.

다음처럼 이어서 요청하면 됩니다.

> 이 보고서를 기준으로 이어서 작업해줘. 기존 결론과 근거부터 확인하고, 새로 필요한 부분만 조사해줘.  
> 지금 고민은 월 9,900원 유료 출시와 무료 프로젝트 제공 중 무엇부터 할지야. 근거가 충분하면 여러 판단 관점으로 재검토하고, 각 선택 이후 고객 반응도 가상 시나리오로 살펴봐줘.  
> 실제 이용 기록과 고객 응답은 아직 없으니 이탈률이나 구매 의사를 만들어내지 마. 결과는 기존 보고서에 추가할 수 있게 정리해줘.

나중에 실제 피드백이 생기면 후기 분석을, 이용 기록이 생기면 이탈과 재방문 분석을 이어 붙이면 됩니다.

**지금 자료로 가능한 기능부터 쓰고, 새 자료가 생기면 해당 판단을 갱신하는 방식입니다. 모든 기능을 매번 한꺼번에 돌릴 필요는 없습니다.**

## 12. 결과를 받을 때 이것만 확인하세요

1. **무슨 자료를 읽었는가?**  
   파일 이름이나 출처가 실제로 확인되는가?

2. **무엇을 실제로 실행했는가?**  
   계산한 결과인지, AI의 해석인지, 앞으로 할 계획인지 구분돼 있는가?

3. **숫자를 다시 확인할 수 있는가?**  
   원래 인원과 기록, 제외 기준, 계산 방법이 남아 있는가?

4. **반대 의견과 모르는 부분도 있는가?**  
   좋은 이야기만 남기거나 부족한 자료를 추측으로 채우지 않았는가?

5. **내가 다음에 무엇을 하면 되는가?**  
   조사 내용이 실제 선택이나 개선할 부분으로 이어지는가?

6. **파일을 준다고 했다면 실제로 열리는가?**  
   “저장했습니다”라는 답변만이 아니라 파일 자체가 있는가?

이 중 빠진 것이 있다면 이렇게 말하면 됩니다.

> 지금 결과에서 실제 확인한 것, 계산한 것, 추정한 것, 아직 실행하지 않은 것을 나눠줘. 중요한 결론마다 근거를 연결하고, 확인할 수 없는 부분은 미확인으로 남겨줘.

## 결과부터 보고 결정하세요

[BriefLoop 시장조사 예시](examples/briefloop/README.md)는 고객의 수정 요청을 관리하는 가상 웹앱을 조사한 결과입니다.

보고서는 무료 폼과 협업 도구를 비교하고, “월 9,900원이 싸 보인다”는 이유만으로 결제 수요가 있다고 판단하지 않았습니다. 첫 고객군을 좁히고, 고객이 기존 메신저 대신 새 링크를 사용할 이유부터 확인하도록 제안했습니다.

**이 예시는 2026년 9월 28일, R2 이전의 method-parity 시험본으로 생성한 내부 가상 사례입니다.** 실제 고객 성과나 최신 R2의 비교 우위를 보여주는 자료는 아닙니다. 원래 입력, 보고서와 출처표를 함께 공개합니다.

## 설치하기

Claude Code 또는 로컬 스킬을 지원하는 Codex가 필요합니다. ChatGPT나 Claude 웹 채팅에 링크만 붙여 넣는 설치 방식은 아닙니다. AI 이용 요금과 사용량은 사용 중인 서비스 기준을 따릅니다.

1. 이 저장소의 **Code → Download ZIP**을 누르고 압축을 풉니다.
2. `skills/fieldpilot` 폴더 **전체**를 아래 위치에 복사합니다. `SKILL.md`만 복사하면 필요한 자료와 도구가 빠집니다.
3. 해당 AI에서 새 세션을 열고 스킬을 호출합니다.

| 사용하는 AI | 현재 프로젝트에 설치할 위치 | 호출 |
|---|---|---|
| Claude Code | `.claude/skills/fieldpilot/` | `/fieldpilot` |
| Codex | `.agents/skills/fieldpilot/` | `$fieldpilot` |

설치된 모양은 다음과 같습니다.

```text
내 프로젝트/
└── .claude/skills/fieldpilot/    # Codex는 .agents/skills/fieldpilot/
    ├── SKILL.md
    ├── references/
    └── tools/
```

여러 프로젝트에서 쓰거나 명령어로 설치하려면 [설치 안내](docs/INSTALL.md)를 참고하세요. 기존 FieldPilot이 있다면 먼저 백업하고, 다른 버전의 파일을 섞지 마세요.

## 이럴 때 써보세요

| 지금 고민 | 이렇게 물어보세요 |
|---|---|
| 만들기 전 | “이 아이디어 이미 많아? 고객은 지금 뭘 쓰고 있어?” |

| 가격을 정할 때 | “월 9,900원 생각 중인데 대안들 가격과 비교해줘.” |

두루뭉술한 질문도 출발점이 될 수 있습니다. 다만 어떤 앱인지 전혀 알 수 없으면 먼저 물어봅니다. 짧은 질문에서 항상 같은 품질이 나온다는 비교 검증은 아직 충분하지 않습니다.

## 파일럿에 넣은 것

**경쟁업계의 조사 방법을 질문에 맞게 꺼내 씁니다.** 시장과 고객, 경쟁사, 가격, 진입장벽부터 인터뷰 해석과 제품 사용 기록까지 다룹니다. 모든 분석법을 매번 돌리지 않고, 지금 판단에 필요한 방법을 고르도록 구성했습니다.

**잘 만들어진 자료부터 찾아봅니다.** 해당 분야의 공식 자료와 전문 분석을 먼저 살피고, 이미 충분한 근거는 활용합니다. 자료가 오래됐거나 서로 충돌하면 그 부분을 더 확인합니다. 유명한 사이트라는 이유만으로 결론을 믿지는 않습니다.

**좋다는 근거와 불리한 근거를 같이 봅니다.** 경쟁사 가격, 사용자의 실제 결제, 가상의 예상 매출을 구분합니다. 출처를 찾지 못했거나 확인할 수 없는 내용은 그대로 남깁니다.

**결과가 생기면 판단을 업데이트합니다.** 이전 보고서와 새 피드백, 가입이나 사용 기록을 함께 주면 무엇이 달라졌는지 비교합니다. 대화 밖에서 자동으로 계속 감시하는 서비스는 아닙니다.

전문 분석 엔진, 유료 패널이나 경쟁사의 비공개 데이터를 모두 포함한 제품은 아닙니다. 필요한 자료가 없으면 실행한 척하지 않고, 추가로 준비할 자료와 조사 방법을 정리합니다.

## 현재 한계

- 최신 공개 자료를 조사하려면 사용하는 AI에 웹 검색과 원문 접근 기능이 있어야 합니다. 로그인이나 유료 자료 접근 권한은 따로 필요할 수 있습니다.
- 결과는 AI 모델과 도구, 제공한 자료에 따라 달라집니다. 일반 AI보다 항상 깊거나 정확하다고 입증된 것은 아닙니다.
- 조사 범위가 넓으면 시간과 AI 사용량이 늘어납니다. 특정 요금제에서의 실행 횟수나 비용 절감을 보장하지 않습니다.
- 실제 고객 인터뷰, 결제나 제품 사용 데이터 없이 매출과 성공을 확정할 수 없습니다. 중요한 출처와 숫자는 사용자가 다시 확인해 주세요.
- 포함된 계산 및 보고서 도구에는 Python 3.10 이상이 필요합니다. 필수 외부 Python 패키지는 없으며 PDF에는 별도 로컬 브라우저가 필요합니다. 처음에는 HTML 출력까지 권장합니다.
