# FieldPilot 기능 가이드

README는 처음 쓰는 사람이 빠르게 이해하도록 핵심만 남깁니다. 이 문서는 현재 공개본에서 사용할 수 있는 주요 분석 경로를 기능별로 설명합니다.

> 기준: `1.9.9-rc04` + `competitor-coverage-01-r2` + `quality-max-01` + `industry-depth-backstop-02` + `market-anchor-01`

## 1. 경쟁사·대체재·레퍼런스 탐색

단순히 같은 카테고리 이름을 가진 제품만 찾지 않습니다.

넓은 조사에서는 상황에 맞게 다음을 분리해 봅니다.

- 직접 경쟁사
- 같은 문제를 다른 방식으로 푸는 대체재
- 수작업 또는 무료 대안
- 특정 행동·워크플로·메커니즘이 닮은 인접 제품
- 전체 카테고리는 달라도 참고할 요소가 있는 component analogue
- 다른 시장에서 같은 경험을 잘 해결한 cross-category reference

각 레퍼런스는 "왜 닮았는지"와 "어디가 다른지"를 함께 봐야 합니다. 비슷한 요소가 있다는 이유만으로 실제 구매 대체재라고 단정하지 않습니다.

## 2. Reference-first 조사

이미 좋은 전문자료가 있으면 먼저 확인합니다.

예:
- 공식 통계
- 회사/제품 원문
- 전문 시장조사 공개자료
- 공신력 있는 산업 자료
- 실제 서비스 출력
- 리뷰/커뮤니티
- 사용자가 이미 가진 조사자료

충분한 자료를 다시 만들기보다 재사용하고, 정의·기간·지역·방법이 맞지 않거나 서로 충돌하는 부분만 추가 조사합니다.

## 3. 시장 앵커: 로컬부터 보고 세계로 확장

사용자가 매번 국가를 적지 않아도 먼저 조사할 시장을 잠정적으로 잡습니다.

우선순위는 `사용자가 지정한 시장 → 제품·스토어·통화·플랫폼 같은 강한 지역 단서 → 대화 언어 기반 잠정 시장 → 언어권 클러스터 → 글로벌`입니다.

- 한국어처럼 특정 상업 생태계와 강하게 연결된 언어는 한국을 잠정 1차 시장으로 먼저 조사할 수 있습니다.
- 영어는 미국으로 자동 지정하지 않고 영어권/글로벌 클러스터로 시작합니다.
- 스페인어·프랑스어·포르투갈어·아랍어처럼 여러 나라에서 쓰이는 언어도 특정 국가를 임의로 고르지 않습니다.
- 언어는 검색 순서를 정하는 힌트일 뿐 실제 타깃 국가, 법적 관할권, 고객 위치의 증거가 아닙니다.

조사 흐름은 `Local-first → Global-best → Local-transfer`입니다. 먼저 잠정 시장의 경쟁사·가격·무료 대안·플랫폼·공식자료를 보고, 전 세계에서 더 좋은 제품과 레퍼런스를 찾은 뒤, 해외의 가격·성공사례·시장규모가 실제 로컬 시장에 옮겨질 수 있는지 다시 확인합니다.

## 4. 산업·시장 전경 백스톱

넓은 시장·사업성 질문에서는 제품과 직접 경쟁사만 보고 결론내리지 않습니다.

일반 심층 리서치가 잘하는 다음 층이 판단을 바꿀 수 있는지 먼저 확인합니다.

- 이 기능이 독립 시장인지, 더 큰 시장 안의 부가기능인지
- 시장 규모·성장률이 실제 결정에 필요한지
- 무료 → 저가 → 주류 SaaS/서비스 → 전문 하드웨어/서비스 → 엔터프라이즈 가격대가 어떻게 나뉘는지
- 기업용 표준, OS/플랫폼 기본 기능, 오픈소스·셀프호스팅 같은 숨은 대안이 있는지
- 보안 사고, 규제, 인증, 플랫폼 정책, 기술 변화가 수요나 진입장벽을 바꾸는지
- 국내와 글로벌의 경쟁·가격·유통 구조가 다른지

처음에는 결정에 필요한 범위만 빠르게 확인하고, 그 결과가 현재 결론을 뒤집을 수 있을 때만 더 깊은 산업 조사로 올라갑니다. 시장이 크거나 성장한다는 사실만으로 내 제품의 수요나 결제 가능성을 올려 쓰지는 않습니다.

## 5. 제품 상태와 시장 비교

코드가 있다는 사실과 실제 사용자에게 제공되는 기능은 다릅니다.

가능할 때 제품/저장소를 확인하고 다음을 구분합니다.

- 구현됨
- 부분 구현
- 계획만 있음
- 확인 불가
- 실제 배포/출시 여부

그 뒤 시장 근거와 비교해 무엇을 유지하고, 바꾸고, 미루거나 확인해야 하는지 연결합니다.

## 6. 가격·결제·상업성

가격표, 관심, 결제, 반복사용은 서로 다른 증거입니다.

FieldPilot은 다음을 가능한 한 분리합니다.

```text
표시 가격
활성 판매 제안
구매 의향
실제 결제
반복 결제/리텐션
검증된 WTP
```

확인되지 않은 단계는 올려 쓰지 않습니다.

## 7. 출시 후 문제 진단

“아무도 안 쓴다”를 한 원인으로 묶지 않습니다.

가능한 원인 예:
- 노출 자체가 없음
- 클릭은 있지만 가입하지 않음
- 가입했지만 핵심 기능을 쓰지 않음
- 사용했지만 돌아오지 않음
- 사용은 하지만 결제하지 않음
- 결제 경로 문제
- 측정이 잘못되어 있음

실제 로그가 있으면 분석하고, 없으면 어떤 이벤트를 기록해야 하는지 설계합니다.

## 8. 실제 피드백·인터뷰 분석

테스터 피드백, 고객 문의, 공개 후기, 인터뷰 원문을 가져오면:

- 반복되는 문제
- 해당 발언 원문
- 몇 명/몇 건에서 나왔는지
- 반대 사례
- AI가 해석한 부분
- 개선 후보

를 분리해 볼 수 있습니다.

한 사람이 여러 번 말한 내용을 여러 고객 의견처럼 세거나, 작은 표본을 시장 전체로 일반화하지 않습니다.

## 9. 설문·1차 조사 설계

공개자료만으로 중요한 불확실성이 해결되지 않을 때 사용할 수 있습니다.

필요한 경우:
- 조사 대상
- 스크리너/제외 조건
- 질문과 응답척도
- 분기/skip logic
- piping/prefill
- 질문/선택지/블록 무작위화
- quota
- 번역/다국어
- 접근성
- 부실응답/QC
- 분석 방법

을 설계합니다.

FieldPilot이 SurveyMonkey/Qualtrics 같은 설문 플랫폼을 자체 호스팅하는 것은 아닙니다. 실행 인프라가 필요하면 적합한 전문 도구를 고르는 방향으로 연결합니다.

## 10. 설문·구조화 데이터 분석

실제 조사 결과를 받으면 가능한 범위에서:

- 원본 보존
- 중복/결측/제외
- 정확한 분모와 base size
- subgroup/crosstab
- 가중치 적용 전후
- 통계적 유의성과 실질적 차이
- 자유응답 topic/sentiment
- 여러 조사 wave의 비교 가능성

을 검토합니다.

소프트웨어가 유의성 표시를 했다고 표본편향이나 측정 문제가 사라지는 것은 아닙니다.

## 11. Decision Council

충분한 현실 근거가 이미 있고 전략 선택을 다시 공격할 필요가 있을 때만 사용합니다.

공개 1차 자료로 확인된 의사결정 원칙을 task-fit lens로 적용해:
- 무엇을 더 중요하게 볼지
- 기존 결론을 무엇이 공격하는지
- 서로 어디서 갈리는지
- 어떤 증거가 결과를 바꿀지

를 확인합니다.

실제 유명 인물이 사용자의 상황을 검토하거나 자문했다는 뜻은 아닙니다.

## 12. Scenario Stress Test

가격, 무료 범위, 타깃 변경처럼 선택 이후 다른 사람의 반응이 중요한 경우 사용할 수 있습니다.

고객/경쟁사/채널 등의 가능한 반응을 시나리오로 살펴보지만, 모든 반응은 가설입니다.

가상 고객 수나 구매확률을 실제 시장 데이터처럼 만들지 않습니다.

## 13. Research Refresh

이전 보고서와 새 자료가 있으면 처음부터 다시 조사하지 않고:
- 무엇이 바뀌었는지
- 어떤 근거가 오래됐는지
- 이전 결론 중 무엇이 영향을 받는지
- 추천이 안정적인지

를 업데이트합니다.

## 14. 전문 보고서

전체 시장조사를 요청하면 실행 환경에서 가능한 형식으로 다음을 정리할 수 있습니다.

- 최종 Markdown
- self-contained HTML
- PDF (검증 가능한 브라우저 경로가 있을 때)
- 출처표
- 경쟁사/사례 매트릭스
- 구조화 CSV/XLSX (실제로 생성·검증할 수 있을 때)

보고서는 길이 자체가 목표가 아닙니다. 필요한 근거와 비교가 많으면 길어질 수 있고, 좁은 질문이면 짧게 끝납니다.

## 15. Quality Max

현재 기본 최적화 우선순위:

```text
정확성·출처
→ 결정에 필요한 범위
→ 유사/인접 제품 발견력
→ 비교 깊이
→ 결정 가치
→ 효율
```

중복만 줄이고, 실제 결과를 차별화하는 발견과 세부 비교는 사용량 절감을 위해 제거하지 않습니다.
