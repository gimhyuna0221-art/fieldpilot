# Advanced Method Execution and Handoff Matrix

Load only when the active question needs a named method below, a user specifically requests it, or a returned specialist output needs review. Read the selected row and the applicable existing method card, not all methods for an ordinary descriptive answer. This is a conditional design, execution-readiness and specialist-handoff contract. It is **not a regression, SEM, MaxDiff or other statistical engine**, and it does not establish performance parity with JMP or any vendor.

The stable IDs follow the supplied-source inventory: M043–M072 are the 30 individually named analysis methods; M013–M014 are the two fieldwork methods. M082 is an additional umbrella-routing entry for data mining, not an invented standalone estimator. Naming a method is not implementing or executing it. With no suitable original data or authorized capable tool, deliver a concrete design/specification and, when useful, a specialist-tool or human-service acceptance brief. Do not manufacture a calculation, field visit, participant, fit diagnostic or capability receipt.

Preserve raw data. Use distinct per-analysis states:

| State | Evidence required and permitted claim |
|---|---|
| `DESIGN_ONLY` | Question, proposed input schema and analysis specification exist. No claim that data were collected, a model was fitted or a result was produced. |
| `EXTERNAL_HANDOFF_REQUIRED` | A named unmet input, permission, runtime or expertise requirement blocks local execution. Deliver the acceptance brief in section 5; a provider name alone is insufficient. |
| `READY_FOR_AUTHORIZED_EXECUTION` | Suitable data, design, validated method specification, authorized existing runtime and safe handling are available. This is readiness, not success. |
| `COMPUTED_UNCHECKED` | A real output/log exists, but material diagnostic, provenance or interpretation checks remain. Do not promote it to a supported decision claim. |
| `CHECKED_RESULT` | The actual result has passed the relevant input, design, method, diagnostic and claim-scope checks, with unresolved limitations visible. This is analysis-specific, not general method/vendor certification. |
| `NOT_APPLICABLE` | The method does not answer the question or its input cannot be validly obtained under the scope. Explain why and choose a justified alternative; do not relabel unsuitable data to force the requested method. |

These states are not a mandatory linear sequence. An unsuitable design can go directly to `NOT_APPLICABLE`; a qualified external return can enter `COMPUTED_UNCHECKED`. Run only within existing permissions. This module grants no permission to buy access, recruit/contact people, install packages, upload private data or deploy a service.

## 2. Source-validation boundary

The tables are **proposed minimum review prompts**, not complete universal statistical procedures or sufficient-validity checklists. `VERIFY` in a row means that its estimator-specific assumptions, diagnostics and decision rules require confirmation from the selected tool's official method documentation or an appropriate primary methodological source before execution. A qualified reviewer resolves consequential uncertainty. If confirmation is unavailable, keep the specification/handoff state; do not guess a test, coefficient, fit cutoff or sample-size rule.

Selected primary documentation was consulted on 2026-09-28 for the narrow facts identified in section 7. A P reference confirms only those stated facts, not the whole row. Remaining technical conditions explicitly remain `VERIFY`. Existing FieldPilot evidence/ethics/claim guards remain applicable independently. Vendor examples or defaults are not universal sample sizes, cluster counts, factor counts, fit cutoffs or proof of optimality.

## 5. Concrete specialist acceptance brief

For an external tool or human analyst, prepare a task-specific brief, using only authorized/redacted data:

- **Selected method and decision:** stable M ID, question/estimand, why it fits, and a simpler method considered.
- **Input package:** schema, variable/level definitions, raw/derived locators, units/nesting, sample/design/weights, missingness/exposure, time windows and exclusions. Identify missing inputs explicitly.
- **Execution scope:** named tool/version or required capability, runtime/access status, privacy boundary, specification/settings and unresolved `VERIFY` items. Do not imply that identifying JMP, Qualtrics or another provider proves access or a suitable edition.
- **Required return:** the row's output objects, reproducible commands/settings or method log, actual estimation warnings, diagnostics, uncertainty and a plain-language scope-bound answer. Request a documented non-result when estimation/design fails.
- **Acceptance/rejection:** reconstruct key bases and transformations; inspect actual artifacts, convergence/diagnostics and claim scope; compare a suitable known fixture or independently checked calculation when feasible. A screenshot labeled PASS or a completed form is not sufficient.
- **Authority and cost:** state any action that still needs permission. Drafting this brief does not send it, upload data, purchase services or recruit participants.
